# OMS-Backend codebase reference

Reference material for the refactor. **Everything in this folder is either
generated from the code or verified against it** — none of it is prose that can
quietly go out of date the way the older `docs/` files have (see
[`DOC_STALENESS.md`](DOC_STALENESS.md), which measures exactly that).

Written 2026-08-26.

## The files

**Start with [`ARCHITECTURE.md`](ARCHITECTURE.md)** — it explains how the system
fits together. The rest are lookup tables you consult from it.

## Regenerating

The three generated files must be regenerated after structural changes, or they
become exactly the problem they exist to solve. Scripts are in the session
scratchpad; they are short and worth moving into `scripts/` as part of Phase 0
so CI can rebuild them:

```bash
python endpoint_inventory.py > docs/codebase/API_SURFACE.md
python model_inventory.py    > docs/codebase/DATA_MODEL.md
python domain_graph.py       > docs/codebase/DOMAIN_GRAPH.md
python mine_invariants.py    > docs/codebase/INVARIANTS.md
python doc_staleness.py      > docs/codebase/DOC_STALENESS.md
```

`ARCHITECTURE.md` is the one file written by hand. It cites the generated ones,
so when a regenerated file contradicts it, the generated file is right.

On Windows set `PYTHONIOENCODING=utf-8` first, and use `.venv\Scripts\python.exe`
— the global interpreter has an incompatible `decouple` and cannot import
settings.

## How to use this during the refactor

**Before touching an app** — read its section in `INVARIANTS.md`. Those
statements are the rules that nothing enforces: no test, no type, no constraint.
They hold only because the last person read them. They are what a refactor
destroys silently.

**Before changing a route** — check `API_SURFACE.md`. A mobile client
(`OMS-app`, a separate repo, not checked out here) consumes this API and cannot
be updated in lockstep. `devices.VersionPolicyMiddleware` exists precisely
because old app versions stay in the field.

**Before changing a model** — check `DATA_MODEL.md` for what else points at it,
and remember several tables are `managed = False`: Django will not migrate them
and the schema is owned elsewhere.

**Before trusting anything in `docs/`** — check `DOC_STALENESS.md` first.

## What is not here

Stated so the gaps are known rather than assumed closed.

- **Not every line of the ~50,600 was read.** Structure, routing, models,
  permissions and the security surface were derived mechanically and are
  complete. Business logic was read in risk order — the scheme engine, the SAP
  posting path, the approval engine — and the rest is covered by
  `INVARIANTS.md` only to the extent the code documents itself.
- **No runtime profiling.** Any performance claim in the plan is a hypothesis.
- **No infrastructure review** — deployment, TLS, reverse proxy, backups.
- **`OMS-app` was not examined.** It is not in this workspace.
